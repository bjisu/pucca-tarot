## 1. 서비스 개요

**한 줄 정의**
78장 타로를 뽑으면, 뿌까가 나의 연애·직장·금전·인간관계 등 생활 전반의 고민을 반말로 다정하게 풀어주는 웹 서비스.

**핵심 컨셉**
사용자가 일상 고민(연애, 직장·진로, 금전, 뷰티, 인간관계, 취미, 학업, 기념일)이 생겼을 때 접속해, 질문을 고르고 타로를 뽑아 뿌까의 해석을 받는다. 딱딱한 점술이 아니라 재미있고 위로가 되는 "일상 속 타로 친구" 경험을 지향한다. 연애·사랑은 8개 카테고리 중에서도 핵심 축이다.

**참고 서비스**
LEO Tarot (nfc-tarot-dev.bigglz.com)의 화면 구조·UI 무드를 기준으로 하되, 캐릭터(뿌까)·말투(반말)·질문 콘텐츠·네비게이션을 본 문서 기준으로 새로 정의한다. 백엔드는 LEO 코드의 아키텍처 패턴(FastAPI + LLM Factory + YAML 페르소나)을 참고한다.

---

## 2. 목표와 성공 지표

**제품 목표**

- 일상의 다양한 고민에 대해 부담 없이 위로와 통찰을 얻는 감성 경험을 제공한다.
- "오늘의 타로"처럼 매일 다시 찾게 만드는 습관형 서비스를 만든다.

**성공 지표 (초기 가설, 추후 조정)**

- 리딩 완료율: 카드를 뽑기 시작한 사용자 중 결과까지 본 비율 70% 이상
- 재방문: 첫 방문 후 7일 내 재방문율 30% 이상
- 후속 대화 사용률: 리딩 후 뿌까와 이어서 대화한 비율 40% 이상

## 3. 타겟 사용자

**주요 타겟**
연애·직장·돈·인간관계 등 일상 고민이 많은 10대 후반~30대. 타로·사주·MBTI 등 가벼운 자기탐색 콘텐츠에 익숙하고, 뿌까 같은 캐릭터에 친근함을 느끼는 사용자.

**사용 맥락**

- 밤에 혼자 이런저런 고민이 떠오를 때
- 연애·이직·소비 등 결정을 앞두고 마음을 정리하고 싶을 때
- 기분 전환 삼아 오늘의 운세가 보고 싶을 때

**사용자가 얻고 싶은 것**
정답이 아니라 "공감"과 "방향". 내 상황을 구체적으로 짚어주고, 지금 무엇을 하면 좋을지 다정하게 알려주는 존재.

## 4. 캐릭터 — 뿌까(Pucca)

**뿌까 — 내 일상을 봐주는 타로 친구**

- **정체성**: 연애든 일이든 돈이든, 사용자의 고민을 진심으로 함께 고민해주는 발랄한 타로 리더.
- **성격**: 밝고 에너지 넘치며 적극적. 사용자를 자기 일처럼 응원하고, 필요할 땐 "이건 아니야, 정신 차려!" 하며 화끈하게 현실 조언도 한다.
- **말투**: **친근하고 발랄한 반말** (확정). 사랑스럽고 에너지 있게, 오글거리지 않게. 참고 서비스의 "~냥" 어미는 사용하지 않는다.
- **해석 원칙**:
  - Cold Reading(누구에게나 맞는 뻔한 말) 방지 — 카드 상징을 근거로 구체적으로.
  - 감정만 읽지 않고 행동 조언까지 — "오늘은 그냥 질러도 돼" 같은 실천적 제안.
  - 미래는 확정이 아니라 가능성임을 항상 전제.
  - 불안·집착을 부추기지 않고 건강한 방향을 지향.
  - 위기 신호(자해 등) 감지 시 점술 대신 도움 자원 안내로 분기.
- **관리 방식**: 페르소나는 프롬프트 파일(`prompts/templates/pucca_persona.yaml`)로 분리 관리하여 말투·성격을 쉽게 수정할 수 있게 한다.

> **저작권**: 뿌까는 부즈(VOOZ Character System)가 권리를 보유한 캐릭터. 본 프로젝트는 **정식 라이선스를 확보하여 진행 예정**이며, 계약 범위(사용 가능 이미지·표현·플랫폼·기간)에 맞춰 캐릭터 활용을 최종 확정한다. 라이선스 확정 전까지 GitHub 저장소는 **Private** 유지를 권장.

## 5. 핵심 기능 (MVP)

홈 메뉴는 3개: **오늘의 타로 / 클래식 타로 / 타로 카드 도감**. (별도의 '질문 타로' 메뉴는 없음)

### 5.0 공통 리딩 구조 — 질문 선택 → 카드 뽑기 → 결과 → 대화

오늘의 타로와 클래식 타로는 아래 구조를 공유한다. 차이는 뽑는 장수뿐(오늘 1장 / 클래식 3장).

**① 질문 선택 화면**

- 상단 히어로: 뿌까 캐릭터 + 안내 문구 ("요즘 어떤 고민이 있어? 골라봐!")
- 질문 입력창: "고민을 선택하거나 직접 입력해봐!" — 직접 입력 가능, 아래 목록 선택 시 자동 입력.
- 카테고리 탭 (가로 스크롤 8개): 💘 연애·사랑 / 💼 직장·진로 / 💳 금전·재물 / 🥑 뷰티·관리 / 🧶 인간관계 / 🧸 취미·덕질 / 🎓 학업·시험 / 🎉 기념일. 선택 탭은 흰색+밑줄 강조.
- 질문 리스트: 선택된 카테고리의 예시 질문을 세로 스택으로 (이모지+질문, 어두운 보라 라운드 버튼).
- 데이터: `data/question_categories.json` (예시 질문 58개).

**② 카드 뽑기 화면 (스와이프 선택)**

- 상단 히어로: 뿌까 + "고민을 생각하면서 카드 N장을 뽑아봐!"
- 선택 슬롯: 뽑을 장수만큼 카드 프레임(클래식 3칸 / 오늘 1칸). 미선택 시 프레임 안에 금색 "미선택" 텍스트. 선택 시 순서대로 채워짐(뒷면 유지).
- 하단 카드 덱: 카드 뒷면들이 **가로 부채꼴/아치형**으로 펼쳐짐. **좌우 스와이프(터치·마우스 드래그)**로 덱을 넘기고, 중앙 카드는 살짝 떠오르며 강조. 중앙 카드 탭 → 슬롯으로 날아가는 선택 애니메이션. 안내 문구 "카드를 좌우로 이동해 보세요".
- 장수 완료 → 결과 화면 (슬롯 카드가 순서대로 뒤집히는 공개 연출).

**③ 결과 화면**

- 선택한 질문을 상단에 표시, 질문 맥락에 맞춘 뿌까의 개인화 해석.
- 하단 `뿌까랑 더 얘기하기` 버튼 → 후속 대화.

### 5.1 오늘의 타로 (1장) — *필수*

- 결과: 카드 이미지 + 한 줄 운세(`reading_sentence`) + 뿌까 해석 + 오늘의 조언.
- **같은 날 재접속 시 같은 카드 유지.**

### 5.2 클래식 타로 (3장) — *필수*

- 포지션: **① 현재 상황 / ② 필요한 조언 / ③ 결과·전망**
- 결과: 3장 카드 + 포지션별 해석 + 종합 해석 + 실천 조언.

### 5.3 타로 카드 도감 — *필수*

- 78장 전체를 슈트별 탭(🌟 Major Arcana / 🪄 Wands / 🍷 Cups / 🗡️ Swords / 🪙 Pentacles)으로 열람.
- 카드 상세: 이름, 의미, 1줄 리딩, 키워드 태그. 데이터: `data/tarot_cards.json`.

### 5.4 후속 대화 (뿌까 챗봇) — *필수*

- 리딩 결과에 대해 뿌까와 이어서 대화 ("그럼 나 어떻게 하면 좋아?").
- 방금 뽑은 질문·카드·해석 맥락을 기억한 채 반말로 대화.

## 6. 네비게이션 규칙 (확정)

| 화면 | 이동 버튼 |
|---|---|
| 홈 | 없음 (메뉴 카드가 진입점) |
| 질문 선택 | **없음** (뒤로가기·홈 모두 없음, 몰입 유지) |
| 카드 뽑기 | **없음** (뒤로가기·홈 모두 없음, 몰입 유지) |
| 타로 결과 | **홈 버튼 1개만** (+ 기능 버튼 "뿌까랑 더 얘기하기") |
| 뿌까와 대화 | 홈으로 / 새 리딩 버튼 |
| 타로 카드 도감 (목록·상세) | 좌측 상단 **뒤로가기 아이콘만** — 원형 배경 없음, 텍스트 없음, 꺾쇠(`<`, chevron-left) 모양. 터치 영역 44px 이상 |

- 브라우저 물리 뒤로가기로 이탈 후 돌아와도 앱 상태가 깨지지 않게 안전 처리.

## 7. 타로 카드 시스템

**덱 구성 — 정통 78장 타로 (구축 완료)**

- **메이저 아르카나 22장 + 마이너 아르카나 56장 = 총 78장.**
- 마이너는 4개 슈트(완드/컵/소드/펜타클) × 14장.
- 카드 데이터는 `data/tarot_cards.json`에 구축 완료. 필드: id, number, name_kr, name_en, arcana, suit, image, meaning(의미), reading_sentence(1줄 리딩), keywords(키워드 4개).
- 전통적 카드 의미를 유지하되, 질문 맥락에 맞춰 뿌까(LLM)가 해석을 확장한다.
- 역방향(리버스)은 현재 미사용(`reversed_enabled: false`). 사용 여부는 추후 결정.

**카드 이미지 (추후 투입)**

- 78장 이미지는 뿌까 IP 가이드에 맞춰 제작 예정. 준비 전까지 **플레이스홀더**(보라/금색 오너먼트 카드 뒷면 + 카드 이름)로 표시.
- 파일명은 `assets/cards/README.md`의 네이밍 규칙을 따르고, `image` 필드 경로와 일치시켜 이미지 투입 시 자동 반영.

## 8. 해석 생성 방식 (AI 리딩)

1. **카드 뽑기**: 78장 중 랜덤 선택 (스와이프 UI는 연출).
2. **재료 결합**: 카드 고정 데이터(meaning·reading_sentence·keywords) + 사용자 질문 + 뿌까 페르소나 프롬프트.
3. **LLM 호출**: LLM Factory를 통해 생성. 같은 카드라도 질문에 따라 해석이 달라진다.
4. **구조화 응답**: Pydantic 스키마로 고정 형식 수신 — 오늘의 타로(한 줄 운세/해석/조언), 클래식(포지션별 3개/종합/실천 조언).
5. **후속 대화**: 세션에 질문·카드·해석 맥락을 유지한 채 챗 진행.

## 9. 기술 아키텍처

**개발·배포 원칙**

- **Cursor에서 직접 개발.** 프로젝트 루트의 `.cursorrules`가 개발 규칙의 기준.
- **GitHub으로 버전 관리.** `.gitignore`로 `.env`, `__pycache__/`, `node_modules/`, `logs/` 등 제외. API 키는 절대 커밋 금지, `.env.example`로 구조만 공유.
- **Firebase 등 외부 BaaS 미사용.** 데이터베이스 없이 시작한다.

**백엔드 (FastAPI — LEO 구조 참고)**

- REST API. LLM 호출은 Factory 패턴(OpenAI/Anthropic/Gemini 교체 가능).
- 페르소나·리딩 프롬프트는 YAML 템플릿 분리 관리.
- 구조화 응답은 Pydantic 스키마.
- 세션(후속 대화 맥락)은 **서버 인메모리 관리**로 시작 (DB·Firebase 미사용). 서버 재시작 시 초기화되는 수준을 MVP로 허용.
- "오늘의 타로 같은 날 동일 카드"는 uuid(또는 익명 식별자)+날짜 기반으로 서버 파일 또는 인메모리 캐시로 처리.

**프론트엔드 (반응형 웹)**

- 모바일 우선 세로 1열, 데스크톱은 중앙 정렬. 프레임워크는 개발 시 결정(예: React/Next.js 또는 Vanilla).
- 카드 스와이프·선택·뒤집기 애니메이션 품질을 핵심으로.
- `?uuid=` 쿼리 파라미터로 사용자 구분 (없으면 익명 처리).

**데이터 (전부 로컬 파일 — 구축 완료)**

- `data/tarot_cards.json` — 78장 카드.
- `data/question_categories.json` — 카테고리 8개 + 예시 질문 58개.
- 카드 이미지: `assets/cards/` 정적 파일 서빙.

## 10. 디자인 가이드

- **무드**: 딥퍼플 신비주의(밤하늘·별·커튼·샹들리에) + 금색 포인트. 참고 서비스와 동일한 무드, 뿌까의 발랄함을 조화.
- **홈**: 큰 라운드(약 24px) 메뉴 카드 스택 — 좌상단 금색 세리프 영문 뱃지(Today's Tarot / Classic Tarot / Tarot Card List) + 중앙 캐릭터 일러스트 + 하단 흰색 굵은 한글 제목·연보라 설명.
- **폰트**: 한글 둥근 고딕 계열(Pretendard 등), 영문 뱃지는 세리프.
- **품질 기준**: 타이포·여백·색·인터랙션 프리미엄 수준. 임시 디자인·기본 템플릿 느낌 금지.
- **성능**: LLM 응답 대기 중 뿌까 로딩 연출("카드를 읽는 중...")로 체감 지연 최소화.
- **콘텐츠 톤**: 불안 조장·단정적 부정 예언 금지.

## 11. 범위 (MVP)

**포함 (In)**

- 오늘의 타로(1장) / 클래식 타로(3장) — 질문 선택(8개 카테고리) 후 스와이프로 카드 뽑기
- 타로 카드 도감(78장) / 후속 대화(뿌까 챗봇)
- 뿌까 페르소나 1종(반말), 네비게이션 규칙(6장) 적용
- 78장 카드 데이터 + 질문 58개 데이터 (구축 완료)
